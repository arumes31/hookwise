Vorbereitung

Die Microsoft-Konfiguration erfolgt im Microsoft Entra Admin Center. Das klassische Microsoft-365-Admin-Center verwaltet zwar dasselbe Verzeichnis, aber nicht die App Registration.

  • Öffentliche HTTPS-URL für Hookwise
  • Rechte für App Registrations und Enterprise Applications
  • Entra ID P1 oder P2 für gruppenbasierte Zuweisungen
  • Zwei Security Groups mit direkten Benutzermitgliedschaften
  • Lokales Break-Glass-Administratorkonto in Hookwise
ZweckBeispielwert
Hookwise URLhttps://hookwise.example.com
Redirect URIhttps://hookwise.example.com/auth/entra/callback
Viewer-Gruppe1st-Level
Operator-Gruppe2nd-Level
Viewer App Role ValueHookwise.Viewer
Operator App Role ValueHookwise.Operator
Vor dem Aktivieren: Das lokale Administratorkonto testen und dessen Zugangsdaten sicher hinterlegen. So bleibt der Zugriff möglich, wenn Entra falsch konfiguriert ist.
01

App Registration anlegen

  1. Im Entra Admin Center Entra ID → App registrations → New registration öffnen.
  2. Als Namen Hookwise eintragen.
  3. Accounts in this organizational directory only auswählen.
  4. Unter Redirect URI den Typ Web auswählen und https://hookwise.example.com/auth/entra/callback eintragen.
  5. Registrierung abschließen und auf Overview die Application (client) ID sowie Directory (tenant) ID notieren.
Redirect URI exakt übernehmen. Schema, Host, Port, Pfad und abschließender Slash müssen mit ENTRA_REDIRECT_URL übereinstimmen. Für Produktion ausschließlich HTTPS verwenden; http://localhost ist nur für lokale Tests.

Falls die URI beim Registrieren ausgelassen wurde: Authentication → Add a platform → Web öffnen, die URI eintragen und speichern.

02

Client Secret erzeugen

  1. In der App Registration Certificates & secrets → Client secrets öffnen.
  2. New client secret wählen, Beschreibung und Laufzeit festlegen.
  3. Nach dem Erstellen sofort den Wert aus der Spalte Value kopieren — nicht die Secret ID.
  4. Auf dem Docker-Host als ./secrets/entra_client_secret speichern und den Dateizugriff auf den Betriebsaccount beschränken.
Secret niemals in Git, die Datenbank oder direkt in eine Umgebungsvariable schreiben. Hookwise liest es über ENTRA_CLIENT_SECRET_FILE aus einer read-only gemounteten Datei.

Microsoft begrenzt Client Secrets derzeit auf höchstens 24 Monate und empfiehlt weniger als 12 Monate. Ablaufdatum und verantwortliche Person in den Betriebsprozess aufnehmen.

04

Microsoft-365-Gruppen zuweisen

  1. Entra ID → Enterprise applications → Hookwise öffnen.
  2. Unter Properties die Option Assignment required? auf Yes setzen.
  3. Users and groups → Add user/group öffnen.
  4. Gruppe 1st-Level auswählen, dann die Rolle Hookwise Viewer wählen und zuweisen.
  5. Gruppe 2nd-Level auswählen, dann die Rolle Hookwise Operator wählen und zuweisen.
Nur direkte Mitgliedschaften. Verschachtelte Gruppen werden bei Enterprise-App-Zuweisungen nicht ausgewertet. Gruppenbasierte Zuweisungen benötigen Entra ID P1 oder P2.

Admin Consent

Bei Assignment required? = Yes können Benutzer nicht selbst zustimmen. Falls die erste Anmeldung eine Consent-Meldung zeigt, unter Enterprise applications → Hookwise → Permissions als Administrator Grant admin consent ausführen.

05

Docker und Hookwise-Umgebung konfigurieren

Die folgenden Werte in der Hookwise-.env-Datei setzen:

ENTRA_ENABLED=true
ENTRA_TENANT_ID=00000000-0000-0000-0000-000000000000
ENTRA_CLIENT_ID=00000000-0000-0000-0000-000000000000
ENTRA_REDIRECT_URL=https://hookwise.example.com/auth/entra/callback
ENTRA_CLIENT_SECRET_FILE=/run/secrets/entra_client_secret
ENTRA_SCOPES=openid profile email
ENTRA_VIEWER_APP_ROLE=Hookwise.Viewer
ENTRA_OPERATOR_APP_ROLE=Hookwise.Operator
ENTRA_AUTO_PROVISION=false

In docker-compose.override.yml den vorhandenen read-only Bind-Mount für hookwise-proxy aktivieren:

services:
  hookwise-proxy:
    volumes:
      - type: bind
        source: ./secrets/entra_client_secret
        target: /run/secrets/entra_client_secret
        read_only: true
        bind:
          create_host_path: false

Die Secret-Datei vor dem Start anlegen. create_host_path: false verhindert, dass Docker bei einem Tippfehler unbemerkt ein leeres Verzeichnis erzeugt.

Stack starten

Lokales Image:

docker compose build
docker compose up -d

GHCR-Image mit explizitem Override:

docker compose \
  -f docker-compose.ghcr.yml \
  -f docker-compose.override.yml \
  up -d

Migration und Health prüfen

docker compose ps
docker compose logs hookwise-migrate
docker compose exec hookwise-proxy flask db current
Erwartung: Die laufenden Services sind healthy, hookwise-migrate wurde erfolgreich beendet und die Datenbank zeigt d9f1a7c4e2b6 (head).
06

Hookwise-Einstellungen prüfen

  1. Mit dem lokalen Break-Glass-Administrator anmelden.
  2. Identity & Access → Entra ID öffnen.
  3. Connection-Status, Tenant ID, Client ID, Redirect URI, Secret-Dateipfad und Scopes prüfen.
  4. Unter App role authorization Hookwise.Viewer und Hookwise.Operator kontrollieren.
  5. Provisionierungsmodus auswählen und Save Entra settings betätigen.
ModusVerhaltenGeeignet für
Pre-provisioned onlyDer Benutzer benötigt sowohl eine Entra-Zuweisung als auch ein aktives Hookwise-Konto.Kontrollierter Rollout
Create accounts automaticallyEin Benutzer mit erkannter App Role wird beim ersten Login als Viewer oder Operator angelegt.Automatisierter Betrieb

In der Oberfläche gespeicherte App-Role-Werte liegen in Redis und haben Vorrang vor den Umgebungsvariablen. Ist Redis nicht erreichbar, verwendet Hookwise die Umgebungswerte.

07

Manuellen Rollen-Override verwenden

  1. Identity & Access → Users öffnen.
  2. Beim gewünschten Entra-Benutzer Authorization auswählen.
  3. Use manual override aktivieren.
  4. viewer oder operator auswählen und speichern.
Der Override ersetzt die Entra-Rolle vollständig. Er addiert keine Rechte. Nach dem Abschalten greift sofort wieder die zuletzt beim Entra-Login synchronisierte App Role. Änderungen werden auditiert und bestehende Sitzungen beim nächsten Request neu ausgewertet.
08

Abnahmetest

Jeden Fall in einem privaten Browserfenster testen oder Microsoft vollständig abmelden, damit ein neues ID-Token ausgestellt wird. Danach im Hookwise Audit Log entra_login beziehungsweise entra_login_denied kontrollieren.

TestbenutzerErwartetes Ergebnis
Nur Mitglied von 1st-LevelLogin erfolgreich, effektive Rolle viewer
Nur Mitglied von 2nd-LevelLogin erfolgreich, effektive Rolle operator
Mitglied beider GruppenLogin erfolgreich, operator gewinnt
Keine zugewiesene App RoleLogin wird abgelehnt

Rollenänderungen benötigen ein neues Token. Nach einer Entra-Gruppen- oder App-Role-Änderung Microsoft abmelden und neu anmelden. Ein lokaler Override wirkt dagegen bei der nächsten Hookwise-Anfrage.
09

Fehlerdiagnose

no recognized Hookwise App Role
  • Benutzer oder direkte Gruppe ist keiner App Role zugewiesen.
  • Das App-Role-Value stimmt nicht exakt mit Hookwise überein.
  • Das Token ist älter als die Rollenzuweisung; vollständig ab- und wieder anmelden.
foreign tenant

Die tid im ID-Token stimmt nicht mit ENTRA_TENANT_ID überein. Tenant ID und verwendetes Microsoft-Konto prüfen.

Entra-Schaltfläche fehlt oder führt zurück zum lokalen Login
  • ENTRA_ENABLED ist nicht true.
  • Tenant ID, Client ID oder Redirect URL fehlen.
  • Die Secret-Datei ist leer, nicht gemountet oder nicht lesbar.
  • Das Python-Paket msal fehlt im Image.
AADSTS50011 / Redirect URI mismatch
  • Den vollständigen Callback aus der Fehlermeldung mit der Web Redirect URI vergleichen.
  • Externes Schema, Hostname und Port des Reverse Proxy prüfen.
  • Einen abschließenden Slash nicht übersehen.
Login funktioniert, neue Gruppenrolle aber nicht
  • Unter Enterprise applications → Hookwise → Users and groups die Rollenzuweisung prüfen.
  • Direkte Gruppenmitgliedschaft des Benutzers bestätigen.
  • Microsoft vollständig abmelden und ein neues Token beziehen.

Installation abgeschlossen

Hookwise speichert keine ID-, Access- oder Refresh-Tokens. Persistiert werden nur die stabile tid/oid-Bindung, die zuletzt abgeleitete Hookwise-Rolle und ein optionaler manueller Override.
